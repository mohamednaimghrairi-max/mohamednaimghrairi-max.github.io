PART A

Omron LD-90 monitoring platform

01
Acquire

Talking to the robot over ARCL

  • Python client over TCP/IP using Omron’s ARCL command language.
  • Polls the robot about every 10 s: battery, position, wheels and motors, navigation, charging, Wi-Fi.
  • Parses the text replies and logs them to CSV while missions run in a loop.
02
Process

From raw logs to mission KPIs

  • Removes idle periods, waiting states and repeated samples at standstill.
  • Detects mission start and end to segment runs automatically.
  • Computes electrical, energy, thermal and connectivity indicators (min, max, mean) per mission.
03
Supervise

A platform operators can use

  • Detects the running mission automatically and tracks its progress step by step.
  • Compares live measurements against reference bands, with alerts, probable cause and recommended action.
  • Three access levels, a history overview and a conversational assistant with live robot context.

One design problem worth mentioning: reference missions were recorded as loops, so they were only valid from the planned starting point. I generalised the references so the same mission can be supervised whatever point the robot starts from.

PART B

Lithium-ion cell: HPPC characterisation and Thévenin model

01
Test

HPPC data at five temperatures

  • Turnigy Graphene 5000 mAh cell.
  • HPPC tests (charge and discharge pulses, rests, several C-rates) at −10, 0, 10, 25 and 40 °C.
  • State of charge computed by coulomb counting.
02
Identify

Four parameters per SOC and temperature

  • ±0.5 A dead band to classify rest, charge and discharge; only 8–12 s pulses are kept.
  • OCV from the rest window before each pulse (median per SOC step); R₀ from the instantaneous voltage drop.
  • Rp and Cp from an exponential fit of the relaxation (Cp = τ / Rp).
03
Validate

Simulate, then compare

  • Interactive simulator: pick temperature, SOC and current profile, get the predicted voltage.
  • Model validated by RMSE between simulated and measured voltage at each temperature.
  • Finding: cold degrades the cell strongly, above all at low SOC.

Limits and next steps: accuracy drops in the cold (31.0 mV at 0 °C, 44.3 mV at −10 °C), where a first-order model no longer captures polarisation; a second-order (2-RC) model is the next step, along with characterising the LD-90’s own battery and recording more reference runs. During the same internship I also trained machine-learning models to predict mission duration, energy use and SOC from telemetry, and built a MiR600 battery model in Simulink. Defended at INSAT on 21 September 2026.

Other work

02 · Academic research · 2025

AI analysis of leakage current on high-voltage insulators

Leakage-current signals from high-voltage insulators under different pollution levels, with the goal of classifying the insulator’s condition from measured electrical features.

Supervised models (KNN, Random Forest, XGBoost, ANN) gave uneven results: each voltage level favoured a different model and none generalised. That led to an unsupervised approach, PCA followed by clustering, which separated the pollution levels much more consistently.

03 · Internship · TIS Circuits (ALL Circuits) · 2025

PCB traceability and quality-control application

A LabVIEW operator interface backed by SQL Server to track functional tests of electronic boards. Each board gets a unique identifier, its three functional tests are followed individually, and the final GO / NOGO status is computed automatically.

Every action in the interface is written to the database immediately, which removed duplicates and gave full traceability. Validated on a sample of 30 boards.

  • LabVIEW
  • SQL Server
  • Traceability
  • Quality control
04 · CNIMI · 2026

MiR600 battery model in Simulink

A physics-based model of a MiR600 heavy-load mobile robot and its battery in MATLAB / Simulink. Speed, payload mass and slope profiles feed a traction-force calculation (rolling resistance, gravity component on the slope, inertia), converted to mechanical then electrical power.

The resulting current drives a battery block that returns SOC, current and voltage. The model also includes SOC-based charging logic, a standby consumption when the robot is idle, and a temperature estimate from Joule losses.

  • Simulink
  • Battery modelling
  • Vehicle dynamics
  • Charging logic
